- Feature toggles persist as `<name>=<on>,<stage>` in `dos-tool.ini`. A choice saved under another stage (or the old `<name>=<on>` form) is ignored, so a promotion (Beta → Stable) actually turns the feature on for players who never touched it. Re-tick after a stage change if you want a non-default.
- `dos-tool.ini` stores only toggles that differ from the default (`Default()` in `core/overlay.cpp`). Writing every toggle froze whatever default was current at first save.
- Native (non-UPROPERTY) field offsets: scan the object's floats twice a few seconds apart and log those that moved by the elapsed time; match against the UE source layout and the Dumper-7 `Pad_*` gap. Guess-by-order was wrong once (0x1FC read 0).
- Skill scripts run through the `~/.claude/skills` symlink: resolve their own path (`readlink -f "$0"`, Python `Path(__file__).resolve()`), else repo-relative paths land in `$HOME` (new-feature.sh once scaffolded into `~/mods/`).
- Dumper-7 `TMap`/`TSet` range-for and `operator[]` do not compile (`SetElement::Value` is private): walk the sparse array (`ForEach` in `features/item-sort/item-sort.cpp`).
- `UObject::FindObjectFast<T>(name)` with the default flag finds nothing (`HasTypeFlag(None)` is 0): pass the cast flag, e.g. `EClassCastFlags::Enum`. Symptom: item-sort stuck on "waiting for game data" in world.
- A native test that `#include`s Lua's `lua_all.cpp` must do so after every std header: Lua's private headers `#define next` etc. and libstdc++ then fails with "macro next passed 2 arguments". `ImGui::MarkIniSettingsDirty` needs `imgui_internal.h`.
- `near` and `far` are empty macros under `<Windows.h>` (clang-cl, DLL build): a variable named `near` in an SDK-free header compiles in the native test and fails in `just build` with "expected expression". Pick another name.
- Adding/removing widgets (AddChild, RemoveChild) from a ProcessEvent listener crashes the game in Slate code (no DoS-Tool frame) whenever the event is a UMG binding during paint or a widget Construct, e.g. opening the shop (#50). Mutate widget trees only when `umg::IsWorldTick(fn)`; other events may only queue work.
- A toggle added to `dos-tool.ini` by hand while the game runs is lost: the running DLL's ImGui rewrites the ini on unload from its in-memory state. Tick it in the Insert menu instead. Builds that lack a feature keep its lines (#69). The ini is CRLF: a `sed` anchored on `$` must match `\r`. Only one person runs `just dev` into a game, from master: swapped-in builds replace each other's DLL.
- Dumper-7 `FName::ToString()` / `GetName()` cut everything up to the last `/`: a package name prints as `H_M_Root_Mesh_04_Skeleton`. For `/Game/...` paths use `Name.GetRawString()` on the outermost outer.
- A pak in `~mods` is locked while the game runs: copying a rebuilt one fails with "Device or resource busy". Quit the game first; paks mount only at startup anyway.
- UE 4.27 Python: `-run=pythonscript` cannot spawn actors (crash in EditorScriptingUtilities); `UE4Editor.exe -ExecutePythonScript=` runs in the GUI but quits the editor afterwards. Set options with `set_editor_property` (attribute names differ, e.g. no `import_morph_targets` attribute); `bUpdateAnimationInEditor` only via `set_update_animation_in_editor`. Import tasks save the meshes, not a skeleton they created or extended: `EditorAssetLibrary.save_loaded_asset(skeleton)`.
- Cook `-map=<non-map package> -cooksinglepackage` cooks nothing of ours; use `+DirectoriesToAlwaysCook` and choose the pak contents with an explicit UnrealPak list.
